## 1. 基本方針
地図は「広げる」より「深める・正す」。自律更新の量は、ユーザーの理解の進み具合を上限とする。

## 2. 1サイクルの優先順位
| 順 | 種類 | 内容 |
|---|---|---|
| 1 | 訂正 | 既存ノードの誤り・古い数値・不正確な表現の修正。発見したら必ず最優先 |
| 2 | 深化 | 現在のセッション（`state.current_session`）の範囲のノードを掘り下げ、詳細ノード（level 4）と証拠・論争を追加 |
| 3 | 問い | `questions.json` の open な問いのうち、ユーザー由来のものを優先して探究 |
| 4 | 拡張 | 現在のセッションに隣接する領域・時代への新規ノード追加 |
| 5 | 時事 | 今回のテーマと地図につながる最近の出来事を1件、教材の第10節に置く |

## 3. 量の上限
| 項目 | 上限 | 条件 |
|---|---|---|
| 新規ノード（1サイクル） | 40 | 直近の評価でL2以上のノードが前回より増えていない場合は20 |
| 新規エッジ（1サイクル） | 80 | |
| 削除 | 制限なし | ただし理由を必ず記録。IDは再利用しない |
| 教材 | 1本（16〜24p、超える場合は分冊） | |

## 4. 次のセッションへ進む条件
- 現在のセッションの主要ノードの過半数が、評価でL2以上になったとき。
- ユーザーが「次へ」と指示したとき（即時）。
- 2サイクル続けて回答がない場合：新しいセッションへは進まず、同じセッションの深化と復習を続け、レポートで状況を伝える（催促はしない）。

## 5. 訂正の扱い
| 重要度 | 基準 | 対応 |
|---|---|---|
| 高 | 結論・理解を変える誤り（例：事実と仮説の取り違え、数値の桁の誤り） | 即時修正。関連ノードの理解レベルに再確認フラグ。レポートの冒頭で知らせる |
| 中 | 数値の更新、表現の不正確さ | 修正。レポートに記載 |
| 低 | 用語の揺れ・体裁 | 修正。レポートには件数のみ |

## 6. 認識ラベルの変更
- ラベルの変更（例：仮説 → 理論、理論 → 論争）は「中」以上の訂正として扱い、根拠となる資料を必ず付ける。
- 「論争」は、査読付き文献・主要機関の資料で複数の立場が確認できる場合に限る。少数意見を同等に扱わない。

## 7. 時事の扱い
- 実行時点で、一次情報（公的機関・研究機関・論文・企業の公式発表）を優先して確認する。
- 報道だけに基づく主張は `confidence: low` とし、教材では「報道ベース」と明記する。
- 時事を地図に入れる場合は、既存の構造（因果・歴史）につなげる。孤立したニュースのノードを作らない。

## 8. 理解レイヤーの更新規則（Examiner）
| レベル | 認定の基準 |
|---|---|
| L1 認知 | 用語と大まかな位置（いつ・どの分野か）を言える |
| L2 説明 | 資料を見ずに、自分の言葉で、誤りなく要点を説明できる |
| L3 専門理解 | 根拠（証拠・理論・数式・史料）と限界を説明できる |
| L4 統合応用 | 他分野と結びつけ、新しい事例に適用できる |
| L5 批判的検証 | 反論・反証・未解明を踏まえ、自分の評価を述べられる |

- 1回の回答で上げられるのは最大2段階。
- 大きな誤解があればレベルを下げてよい（理由を記録）。
- 復習の間隔：評価日から 7日 → 21日 → 60日 → 180日。復習問題で正答できなければ間隔を最初に戻す。

## 9. やってはいけないこと
- ユーザーの回答なしに理解レベルを上げる。
- 出典を確認せずに数値・引用・文献を載せる。
- 「生成AIに関係があるか」で取り上げるテーマを選別する。
- 単一の原因で歴史や社会現象を説明する。
- ユーザーに判断を求める質問をレポートに並べる（確認が必要なのは要件の変更提案のみ）。
