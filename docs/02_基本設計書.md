## 1. 全体構成

```
┌──────────────── GitHub: novatky-cyber/the-universal（正本）────────────────┐
│                                                                              │
│  docs/            設計書・ADR・引き継ぎ資料                                   │
│  agents/          各エージェントの指示書                                      │
│  data/            知識グラフ・理解レイヤー・問い・予測・資料・状態（JSON）    │
│  content/cycles/  サイクルごとの教材・レポートの原稿（Markdown）              │
│  templates/       PDF用のHTMLテンプレートとCSS                                │
│  tools/           検証・変換・PDF生成・差分のスクリプト（Python）             │
│  output/          生成されたPDF（lessons/, reports/）                         │
│  index.html + viewer/   3Dビューア（GitHub Pagesで公開）                      │
└──────────────────────────────────────────────────────────────────────────────┘
        ▲ push                                   │ GitHub Pages
        │                                        ▼
┌───────────────────────┐              ┌──────────────────────────┐
│ Claude（定期実行タスク）│              │ iPhone / iPad（Safari）   │
│  自律学習サイクル       │── 通知 ────▶│  3Dビューア               │
│  ＋サブエージェント     │              │  PDF → GoodNotes          │
└───────────────────────┘              └──────────────────────────┘
        ▲ 回答提出用プロンプト
        │
┌───────────────────────┐
│ Claude（チャット）      │  評価（Examiner）→ 理解レイヤーを更新しコミット
└───────────────────────┘
```

**採用技術と理由**（詳細はADR）
| 要素 | 採用 | 理由 |
|---|---|---|
| データ | JSON＋JSON Schema | 人が読める・Gitで差分が見える・外部DB不要（ADR-0001） |
| ビューア | 静的HTML＋three.js（CDN） | GitHub Pagesで無料公開、ビルド不要（ADR-0002） |
| PDF | Markdown → HTML（Jinja2）→ Chrome印刷（Playwright） | 日本語組版・SVG図・CSSで固定フォーマットを保証（ADR-0003） |
| 自律実行 | Claudeの定期実行タスク | 追加費用なし。各回は新しいセッションで、本リポジトリから文脈を復元 |

## 3. 構成要素

### 3-1. 知識グラフ（data/graph/）
- `domains.json`：10領域（固定。変更は地図のMAJOR更新）
- `nodes.json`：ノードの配列（IDで昇順に並べ、差分を読みやすくする）
- `edges.json`：エッジの配列
- 階層：領域（level 1）→ テーマ（level 2）→ 概念（level 3）→ 詳細（level 4）。`parent` で上位を指す。
- スキーマと属性はDOC-03 §1。

### 3-2. 理解レイヤー（data/understanding.json）
- ノードIDごとに理解レベル（0〜5）、評価履歴（要約）、次回復習日、再確認フラグ。
- 記載のないノードはL0とみなす。

### 3-3. 問いと予測（data/questions.json, data/forecasts.json）
- 問い：ID、本文、出どころ（ユーザー／教材／未解明）、状態、関連ノード。
- 予測：ID、対象、条件、期限、確率、判定基準、更新履歴、結果。予測者（user / claude）を区別。

### 3-4. 資料（data/sources.json）
- ID、書誌、発行者、URL、種別（一次資料／総説／教科書／公的機関／報道）、実在確認（verified / unverified）と確認日。

### 3-5. 状態（data/state.json）とカリキュラム（data/curriculum.json）
- 状態：サイクル番号、地図の版、システムの版、最終実行、現在のセッション、保留事項、次サイクルの予定。
- カリキュラム：Phase → セッション（主題・到達目標・状態・関連ノード）。

### 3-6. 3Dビューア（index.html, viewer/）
画面構成：
| 部品 | 内容 |
|---|---|
| 3Dキャンバス | 全画面。ピンチで拡大、ドラッグで回転、2本指で移動 |
| 上部バー | タイトル、地図の版、検索、表示切替（円筒／展開）、フィルタ |
| 凡例 | 理解レベルの色、ノード種類の形 |
| 詳細パネル | ノードをタップすると下からせり上がる（iPhone）／右側に表示（iPad横） |
| 時間軸 | 目盛り（138億年前、46億年前、6600万年前、1万年前、1000年前、100年前、現在、未来） |

座標系（DOC-03 §3で計算式を定義）
- **円筒表示（既定）**：中心軸＝時間（左が過去、右が未来）、円周方向＝10領域、半径＝詳細度（内側ほど概観、外側ほど詳細。詳細ノードは数が多いため外周の広い面に置く）。時間を持たないノード（思考法・数学的概念など）は中心軸のすぐ近くに「思考の背骨」として並べる。
- **展開表示**：円筒を切り開いた形。奥行き＝10領域のレーン、高さ＝詳細度（上が概観）。円筒の裏側が見えない問題を補う。
- **意味的ズーム**：カメラとの距離に応じて、表示する詳細度とラベルを切り替える。
- 色＝理解レベル、形＝ノードの種類、エッジは選択したノードの関係のみ強調表示（全エッジを常時描くと糸くず状になるため）。

### 3-7. PDF生成（templates/, tools/render_pdf.py）
- 原稿：`content/cycles/NNNN/lesson.md`、`report.md`（frontmatter＋本文。独自記法はDOC-03 §2）。
- テンプレート：`templates/lesson.html.j2`、`templates/report.html.j2`、`templates/print.css`。
- 図：原稿内のSVG、またはデータから自動生成する図（ミニマップ・年表・理解度の推移）。
- 出力名：`output/lessons/L0001_<slug>.pdf`、`output/reports/R0001_<yyyymmdd>.pdf`。

### 3-8. ツール（tools/）
| スクリプト | 役割 |
|---|---|
| `validate.py` | スキーマ検証、参照整合性（エッジ・親・出典・関連ノードの実在）、ID重複、必須ラベル |
| `build_viewer_data.py` | ノード・エッジ・理解レイヤー・領域を `viewer/data/graph.json` に統合 |
| `render_pdf.py` | 原稿 → HTML → PDF、ページ数と必須セクションの検査 |
| `map_diff.py` | 指定したGit参照との差分（追加・変更・削除）を集計 |
| `check_all.py` | 上記をすべて実行し、失敗があれば終了コード1 |

## 4. エージェント構成

### 4-1. 学習パイプライン
| 役割 | 指示書 | 入力 | 出力 | 実行形態 |
|---|---|---|---|---|
| Orchestrator | agents/orchestrator.md | state・ポリシー | 全体の進行、report.md | メインセッション |
| Planner | agents/planner.md | 理解・問い・カリキュラム | plan.md | メインセッション内 |
| Researcher | agents/researcher.md | plan.mdの担当範囲 | research/*.md | サブエージェント（並行2〜4） |
| Challenger | agents/challenger.md | plan.md・research | research/challenge.md | サブエージェント |
| Verifier | agents/verifier.md | 主張リスト＋出典のみ | verification.md | サブエージェント（独立） |
| Cartographer | agents/cartographer.md | 検証済みの主張 | data/graph 更新 | メインセッション |
| Educator | agents/educator.md | 検証済みの内容 | lesson.md | メインセッション |
| Examiner | agents/examiner.md | lesson.md／ユーザーの回答 | questions.md／understanding 更新 | メインまたはサブ |
| Editor | agents/editor.md | PDF | 品質確認の記録 | サブエージェント |

### 4-2. 開発パイプライン
| 役割 | 指示書 | 実行形態 |
|---|---|---|
| Architect | agents/dev.md §Architect | メインセッション |
| Implementer | agents/dev.md §Implementer | メインセッション |
| Reviewer | agents/dev.md §Reviewer | サブエージェント（独立） |
| Tester | agents/dev.md §Tester | `check_all.py`＋必要に応じサブエージェント |

### 4-3. 独立性の担保
- Verifier・Reviewerには、作成者の推論や下書きの経緯を渡さない。成果物・主張リスト・出典・設計書のみを渡す。
- Verifierは各主張に「確認済み／修正要／根拠不足／出典不在」のいずれかを付ける。「確認済み」以外は反映しない（修正して再検証するか、保留）。
