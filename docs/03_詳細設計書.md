**用語ノード（DOC-01 F11）**：あなたのNotionの3つの用語集から、`tools/migrations/0002_import_notion_glossary.py` で取り込む。Notionは読むだけで書き換えない。写すのは名前（題名の「｜」以降は除く）と1〜2文の定義だけで、`summary` に入れる。`level` 4、`time` null、`epistemic` fact、`confidence` medium、`verification.status` unverified、`target_level` 1。出典は資料の種別 `user-note` の3件（`src.notion-ai-glossary`／`src.notion-business-glossary`／`src.notion-general-glossary`、URLは空）。正本のキーは Notion のページID（`notion_id`）で、ノードIDもそこから作る（Notionで題名を直してもIDは変わらない）。既存の用語ノードは更新（upsert）し、定義が変わったものだけ unverified に戻す。Verifier の結果・置き場所・history は保つ。題名は表示用に整える（「｜」以降の副題・先頭の日付・末尾の版番号・仕事の文脈を示す語を除く）。新しい用語の置き場所（主領域と親テーマ）は移行スクリプトの対応表で決め、受け皿として4テーマ（`thm.ai-practice`／`thm.business-practice`／`thm.body-medicine`／`thm.regions-life`）を置く。公開リポジトリのため、顧客の業種・居住地・個人的な行動を推測させうるページ・重複・時点の速報は除外する。除外は notion_id のハッシュと大まかな分類（privacy／duplicate／not-a-term／news-snapshot）だけで指定・記録し（`data/import/notion_glossary_import_log.json`）、題名は公開ファイルに残さない。資料（user-note）には `glossary` 属性を持たせる。Verifier は1サイクルに約10件の定義を確かめ、verified にするか、変更点レポートの「あなたのメモへの指摘」に書く（DOC-04 §2）。

**epistemic の定義**（引き継ぎ資料 §4-10 に対応）
| 値 | 表示 | 意味 |
|---|---|---|
| fact | 事実 | 資料・実験・測定で確認できる |
| theory | 理論 | 強い証拠に支えられた理論・説明（適用範囲あり） |
| debate | 論争 | 複数の学説・解釈が競合している |
| normative | 規範 | 正義・望ましさ・価値の問題 |
| hypothesis | 仮説 | 予測・未検証の説明 |
| unknown | 未知 | 現時点で確定できない |

### 2.2 見出しと必須セクション
- 教材は `## 1. 〜` から `## 14. 〜` までの番号付き見出しを必須とし、その後に `## 付録A`（解答・解説）、`## 付録B`（出典一覧：自動生成）、`## 付録C`（回答提出用プロンプト）を置く。表紙（0）はfrontmatterから自動生成する。
- レポートは `## 1.` から `## 11.` まで。
- 必須番号の欠落は `render_pdf.py` がエラーにする。
- **分冊**：24ページを超える場合は `lesson_a.md`（前編）と `lesson_b.md`（後編）に分ける。frontmatter に `volume: a` / `volume: b` を書く。必須セクションは前後編の合計で判定する。各冊の末尾に `## 付録B 出典一覧（前編／後編）` を置き、その冊で参照した出典を載せる。後編の冒頭には `## 0. 後編の使い方` を置いてよい。

### 2.3 独自記法
| 記法 | 意味 | 表示 |
|---|---|---|
| `{事実}` `{理論}` `{論争}` `{規範}` `{仮説}` `{未知}` | 認識ラベル | 色つきバッジ |
| `[[src:ID]]` | 出典の参照 | 上付き番号（付録Bに一覧） |
| `[[node:ID]]` または `[[node:ID|表示名]]` | 地図のノードへの参照 | 下線つきの語＋ノードID |
| `:::point 見出し` … `:::` | 要点の枠 | 青枠 |
| `:::analogy 見出し` … `:::` | たとえ | 黄色の枠 |
| `:::caution 見出し` … `:::` | よくある誤解 | 赤枠 |
| `:::exercise 見出し` … `:::` | 演習 | 緑枠 |
| `:::write 見出し lines=N` … `:::` | 書き込み欄 | N行の罫線 |
| `:::background 見出し` … `:::` | 導入・背景（なぜこの問題が生まれたか） | 英字ラベル BACKGROUND |

| 生のSVG／HTML | 図表 | そのまま埋め込み |

**認識ラベルの付け方**（v3.2、L0000の検証指摘による）：ラベルは主張1つに1つ付け、主張の直後に置く。確かさの違う主張（例：区分の由来は事実、その適用は論争）を一文にまとめない。文を分けてそれぞれに付ける。研究の結果（数値）は {事実}、その解釈・説明は {理論} か {論争}。「〜すべき」の部分だけに {規範} を付ける。サイトのトップページや概説ページは、そのページに書かれていない具体的な数値・年代の出典にしない。

## 3. 3Dビューアの座標計算

### 3.1 時間 → x
- `ya`（何年前）を対数に変換：`x = −K · log10(1 + ya)`（過去）、`x = +K · log10(1 + |ya|)`（未来、yaが負）。K = 10。
  - 例：現在 0、100年前 −20、1万年前 −40、6600万年前 −78、46億年前 −97、138億年前 −101。
- `end_ya` があるノードは、始点と終点の x の平均。
- 時間を持たないノード：中心軸付近（半径1.5）に置き、x は主領域ごとに等間隔で −95〜−5 に分散。
- 用語ノード（type `term`）：思考法の外側に薄い殻として置く（半径 3.2〜5.4、展開表示では y = −11）。x の等間隔の割り当ては、用語とそれ以外で別の列にする（用語が増えても他のノードの位置が動かないように）。
- 関係線と親子線は、表示されているノードどうしだけを描く（NOTES を隠したときに、見えない用語への線を残さない）。

### 3.2 円筒表示
- 角度：`θ = 2π · (i + 0.5) / 10 + j`。i は主領域の番号（0〜9）、j はIDのハッシュによる ±0.35·(2π/10) のずらし。
- 半径：level 2 → 6、level 3 → 10、level 4 → 14（ハッシュで ±1 ずらす）。
- 位置：`(x, r·cosθ, r·sinθ)`。

### 3.3 展開表示
- `z = (i − 4.5) · 9 + ハッシュで ±2.5`、`y = (4 − level) · 7`（テーマが最上段）、x は共通。
- 切替時は1秒で補間アニメーションする。

### 3.4 意味的ズームと表示
| カメラ距離 | ラベル表示 |
|---|---|
| 190超 | ノードのラベルなし（領域名と時間軸のみ） |
| 95〜190 | テーマ |
| 45〜95 | テーマ＋概念 |
| 45未満 | すべて |

- 画面上で重なるラベルは、優先度（選択中 ＞ 上位の階層 ＞ カメラに近い）の低いものから隠す。同時表示は最大70件。
- **縦長の画面（iPhone）**では時間軸を縦に置く（下が過去、上が現在）。横長の画面では横に置く（左が過去）。
- 詳細パネルを開いたとき、幅900px未満の画面では描画の中心を上へずらし、選択ノードがパネルに隠れないようにする。

- 色（理解レベル）：生成り→朱赤のグラデーション。L0 `#5c5c5c`／L1 `#e9dcc0`／L2 `#e6be96`／L3 `#e0966d`／L4 `#d46a45`／L5 `#c8402a`
- 形（種類、すべてワイヤーフレーム）：theme 二十面体（大）／concept 二十面体（小）／event 八面体／actor 立方体／theory 十二面体／evidence 四面体／question 輪／method 正四面体の対（星形）／term 小さな六角柱
- エッジ：すべての関係と親子関係を極細・低不透明度の線で常に描く。選択時は関係線だけを白く強調し、他のノードを暗くする。
- 時間の層：各目盛りの位置に、円筒表示では輪、展開表示では長方形の枠をワイヤーフレームで描く。

### 4.2 ページ数の検査
- 教材：16〜24ページ。16未満は警告（内容の不足を疑う）。24超はエラーとし、分冊（`lesson_a.md` / `lesson_b.md`）を求める。
- レポート：4〜8ページ。範囲外は警告。

## 5. 変更点の集計（map_diff.py）
- 入力：比較元のGit参照（既定は `state.json` の `map_refs` にある直前の版のコミット）。
- 出力：追加・削除・変更されたノードとエッジの一覧（変更は属性ごと）、領域別の件数。JSONとMarkdownの両方。
- サイクル完了時に、`data/state.json` の `map_refs` に「版 → コミット」を記録する（タグはpushできない環境があるため、こちらを正とする）。可能なら `map-v<版>` タグも付ける。

## 6. エラー処理
| 事象 | 対応 |
|---|---|
| スキーマ検証の失敗 | マージしない。原因を `state.pending` に記録 |
| 出典の実在を確認できない | `existence: unverified`。教材の根拠に使わない |
| PDF生成の失敗 | HTMLを `output/debug/` に残し、マージしない |
| 利用上限への接近 | 調査範囲を縮小し、レポートに明記 |

### 3.7 2D表示（v3.0）
- 3つの表示：`CYLINDER`（3D円筒）／`UNROLLED`（3D展開）／`PLANE`（2D平面）。画面下部と SETTINGS の VIEW で切り替える。選んだ表示は端末に保存する。
- 2Dの座標：x＝時間（3Dと同じ対数）、y＝10領域のレーン（上から D01〜D10）、レーン内の上下＝詳細度（テーマが上）。具体的には展開表示の座標 (x, y, z) から `(x, −z + (y − 7) × 0.35, 0)`。
- 操作：回転を止め、1本指（左ドラッグ）で移動、ピンチ（ホイール）で拡大縮小。カメラは平面を真上から見る。縦長の画面では3Dと同じく時間軸を縦（下が過去）にする。
- 補助線：レーンの境界線、時間の目盛りの縦線、レーンの左端に領域名。

### 3.8 操作性（v3.1）
ユーザーの主な用途（DOC-01 §2）に対し、必要な操作の回数を減らし、今どこにいて何が効いているかを常に見えるようにする。

| 用途 | 改善 | 仕様 |
|---|---|---|
| U2 現在地の確認 | **NOW 表示とフォーカス** | 画面左上のワードマークの下に「NOW — セッションID 題名」を出す。タップすると、そのセッションの主要ノード以外を淡くする（FOCUS）。もう一度タップするか、チップの × で解除 |
| U1 教材を開く | **メニューの NOW カード** | メニューの先頭に、現在のセッション、最新の教材PDF（前編・後編）、最新のレポートPDFを置く。1タップで開ける |
| 探す | **地図上の検索** | 画面右上に SEARCH を置き、地図の上に検索欄を開く（入力欄に自動でフォーカス）。結果を選ぶとその場所へ移動。メニュー内の検索は残す |
| 状態の把握 | **絞り込みチップ** | FOCUS や領域の絞り込みが効いているときは、画面上部にチップ（例：`FOCUS P01-S01 ×`、`DOMAIN D03 ×`）を出し、× で解除できる |
| 見回す | **ズームと FIT** | 画面下部の右に `−`／`+`／`FIT`。FIT は表示ごとの初期の視点に戻す。ピンチ操作に慣れていなくても使える。現在の表示の詳しさ（DOMAINS／THEMES／CONCEPTS／DETAILS）は小さく併記（幅420px以下の画面では省略） |
| たどる | **戻る・パンくず** | 詳細パネルの上部に、領域 › テーマ › … の位置（パンくず。各段をタップで移動）と、直前のノードへ戻る「← BACK」 |
| 学ぶ | **教材ボタン** | ノードがカリキュラムのセッションに属し教材PDFがあれば、パネルの上部に `LESSON セッションID 前編 ↗ 後編 ↗` |
| 横向きのiPhone | **パネルの位置** | 高さ500px以下の横向きでは、詳細パネルを右側に出し、パネル表示中は NOW とチップを隠す |
| 初めて使う | **初回の案内** | 初回だけ、4項目の案内（タップで詳細、ドラッグ・ピンチと − + FIT、NOW、SEARCH と MENU）を出す。OK で閉じ、端末に記憶する |

- 強調の優先順位：選択中（関係するノードを強調）＞ FOCUS ＞ 通常。FOCUS は範囲のノードを画面に収め（外接球から距離を決める）、範囲外をさらに淡くする。領域の絞り込みと併用したときは、表示中のノードだけで描き、範囲が空ならチップに「該当なし」と出す。
- ラベルは、HUD・NOW・チップ・下部の操作部の実寸の範囲には置かない。
- パンくずの領域の段は、メニューの目次のその領域を開く。
- 操作部はすべて文字のリンク（枠のあるボタンを使わない、ADR-0004）とし、タップ領域は44px以上。
