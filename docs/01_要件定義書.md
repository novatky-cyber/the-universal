## 1. 目的：このシステムは何のために作るのか

### 1-1. 一文で言うと
**あなたの頭の中に「世界の地図」を育てるための、外部の足場（スキャフォールド）と稽古場。**

たとえるなら登山。このシステムは「地形図」「踏破記録」「ガイド」であり、山を歩くのはあなた自身。地形図がどれほど精密でも、歩かなければ登頂したことにはならない。

### 1-2. 何ではないか
- **百科事典ではない**：網羅性ならWikipediaや書籍、Claude自身のほうが上。ノード数の多さを成果としない。
- **真理のデータベースではない**：すべての記述は「現時点での理解」であり、認識ラベル（事実／理論／論争／価値判断／予測／未知）と出典・日付を持つ暫定版。
- **理解の代替ではない**：Claudeが作った説明を読むことと、あなたが理解したことを同一視しない（引き継ぎ資料の原則）。

### 1-3. 作る価値（他の手段にない3点）
1. **「Claudeが知っていること」と「あなたが説明できること」の差が見える**：二層構造により、未踏の領域と理解の穴が地図上で分かる。
2. **知識が時間とともに正しくなっていく**：誤りの訂正・新しい知見・時事が反映され、その差分が毎回レポートされる。
3. **知識が「使える」形で鍛えられる**：説明・応用・予測・反論の演習と、その記録（理解レベル・予測の校正）が残る。

### 1-4. 最終的な成功の姿
- 中核領域（生成AIと、その成立条件）について、**このシステムを開かなくても**全体像・因果・証拠・未解明を自分の言葉で説明できる。
- ニュースや仕事上の事象に出会ったとき、頭の中の地図に置き、12の分析軸と8つの思考法で分析し、条件付きの予測を立てて後から検証できる。
- 「どこまで分かっていて、何が分かっていないか」を言える（知的謙虚さ）。

**成功指標（KPI）**：理解レベルL2以上・L4以上のノード数と目標比／説明課題の合格率／予測の校正（Brierスコア等）／自分で見つけた誤り・反例の数。**ノード総数やページ数は成功指標にしない。**

## 3. 設計原則

1. **理解が主、システムは従**：自律更新の量は、あなたの学習ペースを上限とする。
2. **広げるより深める・正す**：更新の優先順位は、①誤りの訂正、②学習中の範囲の深化、③あなたの問いへの回答、④隣接領域の拡張、⑤時事の反映。
3. **問いが駆動する**：各サイクルは「中心の問い」から始まる。答えだけでなく未解明の問いも地図の一部とする。
4. **認識を区別する**：すべての主張に認識ラベル・確信度・出典・検証日を付ける。
5. **多視点**：主要なノードには、異なる学派・地域・立場からの見方と、最も強い反論を含める。
6. **作る者と確かめる者を分ける**：執筆したエージェントと検証するエージェントを別にし、検証役には執筆過程を見せない。
7. **生成AIは入口であって、物差しではない**：宗教・芸術・歴史などを「AIに役立つか」で評価しない。
8. **すべての変更を追跡できる**：知識もシステムも版管理し、差分を必ずレポートする。

## 4. 機能要件

### F1. 知識グラフ（知識レイヤー）

**ノードの種類**
| 種類 | 例 |
|---|---|
| 概念 Concept | エントロピー、自然選択、資本主義 |
| 出来事 Event | 再結合（約38万年後）、産業革命、Transformer論文（2017） |
| 主体 Actor | 人物・組織・国家・文明 |
| 理論 Theory | ΛCDMモデル、インフレーション理論 |
| 証拠 Evidence | CMB、赤方偏移、軽元素の存在比 |
| 問い Question | 時間に起源はあるか、なぜ2020年代に生成AIが普及したか |
| 予測 Forecast | 条件・期限・確率・判定基準付きの予測 |
| 資料 Source | 論文・書籍・公的機関の資料（実在確認済み） |
| 思考法 Method | 因果推論、ベイズ的更新ほか8種、9つの共通質問、12の分析軸 |

**ノードの属性**：ID／名称（日・英）／定義／詳細本文／領域（10領域、複数可）／時間（開始・終了・不確実性の幅。時間を持たないノードも可）／空間スケール／**認識ラベル**（事実・強い証拠のある理論・解釈と論争・規範的判断・予測と仮説・未知）／確信度／出典リスト／最終検証日／詳細度（概観〜専門）／目標理解レベル／版。

**関係（エッジ）の種類**：原因となる／可能にする／前提とする／部分である／先行する／支持する／対立する／類比である／事例である／思考法を適用する。エッジにも認識ラベルと出典を付ける（「AがBを引き起こした」自体が論争であり得るため）。

**階層**：領域 → テーマ → 概念 → 詳細 の4段。上位ノードは下位ノードの要約を持ち、全体から詳細への掘り下げを可能にする。

### F2. 理解レイヤー（あなたの理解地図）
- 各ノードについて、あなたの理解レベル **L0（未学習）〜L5** を保持する。
  - L1 認知／L2 自分の言葉で説明／L3 専門的な理論や実証の理解／L4 分野横断の統合・応用／L5 反証や限界を踏まえた批判的検証
- **更新できるのは評価エージェントだけ**。根拠はあなたの回答（説明・問題・演習）に限る。Claudeが教材を作っただけでは上がらない。
- 時間経過による忘却を考慮し、復習の時期を管理する（間隔反復）。
- 知識レイヤーの内容が大きく変わったノードは「再確認」フラグを立て、次回の教材で復習させる。
- 目標レベル：生成AIの中核とその成立条件はL4〜5、周辺領域はまずL2（引き継ぎ資料の方針）。

### F3. 問いの在庫と予測台帳
- **問いの在庫**：あなたの疑問・未解明問題・教材から派生した問いを登録し、状態（未着手／探究中／一応の答えあり／未解明として整理済み）を管理する。学習計画の入力にする。
- **予測台帳**：予測ID・対象・条件・期限・確率・判定基準・更新履歴・結果を記録する。期限が来たら自律サイクルで判定し、校正の結果をレポートする。予測を立てるのはあなた（Claudeの予測は参考として区別する）。

### F4. 3Dビューア（Webアプリ）
- **座標型の3D地図**
  - 横軸：時間（対数スケール。宇宙の138億年から現代・未来までを1画面に収める）
  - 円周方向：10領域
  - 高さ：詳細度（上ほど概観、下ほど専門的な詳細）
  - 時間を持たないノード（数学・思考法など）は中心軸の帯に置く
  - 色：あなたの理解レベル／形：ノードの種類／線種：関係の種類
- **意味的ズーム**：引くと領域の「大陸」、寄ると概念、さらに寄ると証拠・論争・出典が現れる。
- **ノード詳細パネル**：定義・本文・認識ラベル・出典・関係・理解レベル・関連する教材PDFへのリンク。
- **検索とフィルタ**：名称、領域、時代、認識ラベル、理解レベル、Phase。
- **補助ビュー**（MVP後）：学習経路ビュー／理解ヒートマップ／問いの一覧／予測台帳／版の比較（地図の差分）。
- **対応端末**：iPhone・iPadのSafariを主とする。重い場合は2D表示に切り替えられる。
- 閲覧専用。編集はClaudeのパイプライン経由でのみ行う。

### F5. 自律学習サイクル（週1回）
定期実行タスクとして、以下を1サイクルで行う。

1. **計画**：理解レイヤー・カリキュラム・問いの在庫・前回の評価結果から、今回の中心テーマと問いを決める
2. **調査**：複数のエージェントが並行して、一次資料・信頼できる二次資料を調べる
3. **反論・多視点**：別の学派・地域・立場からの見方と、最も強い反論を集める
4. **検証**：独立した検証エージェントが、主張と出典を突き合わせ、資料の実在を確認し、認識ラベルを点検する
5. **地図の統合**：重複を除き、ノードと関係を追加・修正し、データ構造の検証を通す
6. **教材執筆**：教材PDFを作る
7. **問題作成**：説明課題・確認問題・前回分の復習問題を作る
8. **レポート**：変更点レポートを作る
9. **品質確認**：PDFのフォーマット・ページ数・図表・リンクを点検する
10. **公開と通知**：リポジトリに反映し、ビューアを更新し、あなたのスマホに通知する

検証に通らなかった変更は反映せず、レポートの「保留事項」に記載する。

**カリキュラム**：引き継ぎ資料の Phase 01（8回）→ Phase 02（生成AIの成立条件の深掘り）→ Phase 03（歴史・経済・政治・国際・哲学・宗教・文化への展開）→ Phase 04（現実の問題への応用と予測）を基本線とし、理解度と問いに応じて順序と深さを調整する。12週という期間は固定しない。

### F6. マルチエージェント構成

**学習パイプライン**
| 役割 | 担当 |
|---|---|
| 指揮（Orchestrator） | サイクル全体の進行、各役割への依頼、統合判断 |
| 学習計画（Planner） | 次のテーマ・問い・深さの決定、カリキュラムの調整 |
| 調査（Researcher ×複数） | 領域・観点ごとに並行して調べる |
| 反論・多視点（Challenger） | 異説、反例、地域・学派による偏りの指摘、最も強い反論 |
| 検証（Verifier） | 主張と出典の照合、資料の実在確認、認識ラベルの点検。**執筆過程を見ない独立役** |
| 地図編集（Cartographer） | グラフへの統合、重複排除、関係付け、データ構造の検証 |
| 教材執筆（Educator） | 教材本文、図解、用語集 |
| 評価（Examiner） | 問題作成、あなたの回答の採点、理解レイヤーの更新 |
| 編集・品質確認（Editor） | PDFの体裁、フォーマット準拠、ページ数、読みやすさ |

**開発パイプライン**（システム自体の改修）
| 役割 | 担当 |
|---|---|
| 設計（Architect） | 設計書の作成・改訂、設計判断の記録 |
| 実装（Implementer） | 設計書に基づくコード実装 |
| レビュー（Reviewer） | 実装の独立レビュー |
| テスト（Tester） | テストと受け入れ基準の確認 |

1サイクルで動かすエージェント数は、利用上限の範囲に収まるよう指揮役が調整する。

### F7. PDF出力（2種、固定フォーマット）

**共通仕様**：A4縦／本文11pt前後の日本語フォント／**右側に約45mmの書き込み余白**（GoodNotes用）／認識ラベルを色とアイコンで表示／版・日付・サイクル番号をヘッダーに表示／図はベクター形式で拡大しても劣化しない。

**① 学習教材（標準16〜24ページ）**
| # | セクション |
|---|---|
| 0 | 表紙：テーマ、中心の問い、地図上の位置（ミニマップ）、前提となるノード |
| 1 | 前回までの復習問題（間隔反復） |
| 2 | 今回の地図：位置づけと全体像の図 |
| 3 | 中心の問い：なぜこれを問うのか |
| 4 | 本論：概観 → 仕組み → 詳細 |
| 5 | 証拠：どうやって知るのか |
| 6 | 論争・異説・別の視点（学派・地域） |
| 7 | 未解明：何が分かっていないか |
| 8 | 他領域とのつながり（生成AIとの接続を含む。ただしAIに還元しない） |
| 9 | 思考法の適用演習（8種から1つ以上） |
| 10 | 現在とのつながり：時事を地図に置く |
| 11 | 用語集（日本語・英語・短い定義） |
| 12 | 自分の言葉で説明する課題（書き込み欄つき） |
| 13 | 確認問題 |
| 14 | 次に読む文献（実在確認済み）と次回予告 |
| 付録 | 解答・解説（別ページ）、出典一覧、**回答提出用プロンプト**（チャットに貼るだけで評価に回せる文面） |

**知識をこぼさないためのルール**：ページ数より網羅を優先する。24ページに収まらない場合は前編・後編に分冊し、内容を削って収めることはしない。

**② 変更点レポート（標準4〜8ページ）**
| # | セクション |
|---|---|
| 1 | 今回のサマリ（3〜5行） |
| 2 | 版情報（地図の版、システムの版） |
| 3 | 知識の追加・変更・削除（一覧と理由） |
| 4 | 誤りの訂正（重要度つき。何が、なぜ、どう変わったか） |
| 5 | あなたの理解への影響（再確認が必要なノード） |
| 6 | 理解レイヤーの推移（評価結果） |
| 7 | 新しい問い・未解明の問題 |
| 8 | 予測台帳の更新（判定と校正） |
| 9 | 保留事項（検証に通らなかったもの） |
| 10 | システムの変更（開発の変更点） |
| 11 | 次のサイクルの計画 |

### F8. 理解確認ループ
1. あなたが教材で学び、説明課題・確認問題に取り組む（手書きでも可）
2. 教材付録の「回答提出用プロンプト」をClaudeのチャットに貼り、回答を送る（文章、または手書きページの写真）
3. 評価エージェントが採点し、講評・誤解の指摘・追加の問いを返し、理解レイヤーを更新する
4. 次のサイクルの計画と復習問題に反映する

回答しなかった週も、サイクルは止めずに進める。ただし未評価のノードは理解レベルを上げず、新規拡張の量を抑える。

### F9. 初期データの投入
引き継ぎ資料から、以下を初版（地図 v1.0）として投入する。
- 10領域、3軸、5つの地図、12の分析軸、9つの共通質問、8つの思考法
- 長期年表（宇宙・地球・生命）、人類・文明史、近現代の索引
- Phase 01 第1回の内容（時間の起源、ビッグバン、3つの証拠、ΛCDMの内訳、時間の矢）
- 第一の探究テーマ（生成AIが2020年代に急速に発展・普及した条件）と、AIの歴史的座標
- 問いの在庫：時間の起源など。第1回の問1は「未回答」として登録する
- 理解レイヤーはすべてL0（未評価）から始める。第1回は「講義提示済み・未評価」とする
- 参考資料は投入時に実在を再確認し、確認できないものは「未確認」とする

## 5. 非機能要件

| 区分 | 要件 |
|---|---|
| 正確性 | すべての主張に出典・認識ラベル・検証日を付ける。資料・URLは実在を確認する。数値は原典で照合する。時事は実行時点の一次情報で再確認する |
| 追跡性 | 知識とシステムの全変更をGitで管理する。地図の版（例：v1.3）とシステムの版（例：v1.2.0）の2系統で管理する |
| コスト | 追加費用0円（Claudeの契約プランとGitHubの無料枠の範囲） |
| 利用上限 | Claudeプランの利用上限の範囲で動かす。超えそうな場合は調査の範囲を縮小し、レポートに明記する |
| 保守性 | データはJSON＋Markdownの人が読める形式で持ち、スキーマで検証する。外部サービスへの依存は最小限にする |
| 継続性 | 各実行は記憶のない新しいセッションで始まる前提で、必要な文脈をすべてリポジトリ内（設計書・ルール・状態ファイル）に置く |
| 端末 | ビューアはiPhone・iPadのSafariで動作する。PDFはGoodNotesで快適に閲覧・書き込みできる |
| プライバシー | 氏名・勤務先などの個人を特定する情報を保存しない。公開リポジトリの場合、あなたの回答は原文を保存せず、評価の要約と理解レベルのみを保存する |
| 障害時 | 実行が失敗した場合は途中の変更を反映せず、失敗内容を次回のレポートに記載する |

### 6-2. 開発ルール（要旨。詳細はCLAUDE.mdに定める）
1. **設計書が先、実装が後**：設計書にない変更はしない。変更する場合は先に設計書を改訂する。
2. 作業はブランチで行い、レビューとテストに通ってから本流に反映する。
3. 実装者とレビュー担当は別のエージェントにする。
4. 変更ごとにCHANGELOGを更新し、重要な判断はADRに記録する。
5. 要件（本書）の変更は、あなたの承認を必要とする。それ以外の設計・実装の判断はClaudeが行い、レポートで報告する。
6. 引き継ぎ資料の品質基準（10項目）を、学習パイプラインの守るべき規則として組み込む。

## 8. 前提・制約・リスク

| リスク | 対策 |
|---|---|
| 誤情報（AIによる幻覚を含む） | 独立した検証役、出典の実在確認、認識ラベル、保留の仕組み |

| 利用上限への到達 | エージェント数・調査範囲を自動で調整し、レポートに明記する |

| 公開リポジトリでの情報露出 | 個人を特定する情報や回答の原文を保存しない |
| 要件の肥大化 | MVPの範囲を守り、追加要望はP5の候補として管理する |

## 10. MVPの受け入れ基準
1. 初期データ（F9）がスキーマ検証を通り、3Dビューアで領域・時間・詳細度の座標に配置されて表示される
2. iPhoneのSafariで、全体表示 → 領域 → ノード詳細まで掘り下げられ、検索できる
3. 理解レベルが色で表示され、L0〜L5の変化がビューアに反映される
4. 定期実行1回で、教材PDF（16〜24ページ、F7①の全セクション）と変更点レポート（F7②の全セクション）が生成される
5. 教材のすべての主張に認識ラベルと出典があり、検証エージェントの検証ログが残っている
6. 回答提出用プロンプトからの回答が採点され、理解レイヤーが更新される
7. 設計書一式・CLAUDE.md・CHANGELOG・ADRがそろい、実装と内容が一致している
