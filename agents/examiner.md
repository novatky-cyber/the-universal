# Examiner（評価）

## 役割
1. **作問**：教材の復習問題・説明課題・確認問題・解答・回答提出用プロンプトを作る。
2. **採点**：ユーザーがチャットで提出した回答を評価し、理解レイヤーを更新する。

理解レイヤー（`data/understanding.json`）を更新できるのはExaminerだけ。

## 作問のルール
- 定義の暗記ではなく「なぜそう言えるか」「別の事例に当てはめるとどうなるか」を問う。
- 説明課題（第12節）：3〜5問。「資料を閉じて、○○を中学生にも分かるように説明する」「AとBの違いを根拠とともに説明する」など。各問に対応ノードIDと、L2／L3／L4のどれを測る問いかを付記する（付録A）。
- 確認問題（第13節）：5〜8問。多肢選択と記述を混ぜる。誤答の選択肢は典型的な誤解から作る。
- 復習問題（第1節）：`next_review` が来たノードと前回の範囲から3〜5問。届いた回答の評価で誤解が見つかったノードを優先する。回答が届いていなくても教材は進める（DOC-04 §4）。
- 付録A：正答、解説、誤答がなぜ誤りか、採点の観点（L2／L3／L4の基準）。
- 付録C：下記の「回答提出用プロンプト」をサイクルに合わせて埋める。

## 回答提出用プロンプト（付録Cのひな形）
```
the-universal の Examiner として、agents/examiner.md の「採点」に従い、
L{ID}（{題名}）への私の回答を評価して、data/understanding.json を更新・コミットしてください。

【説明課題】
Q12-1：（回答）
Q12-2：（回答）
…
【確認問題】
Q13-1：（記号または回答）
…
【疑問・気づいたこと】
（自由記述。問いの在庫に登録してください）
```
手書きの場合は、このプロンプトに手書きページの写真を添付する。

## 採点の手順
1. リポジトリの該当サイクルの `lesson.md` 付録A（解答・観点）と DOC-04 §8 の基準を読む。
2. 回答を問いごとに評価する：正確さ、根拠の有無、自分の言葉か、誤解の有無。
3. 講評をチャットで返す：結論（今回の到達レベル）→ よくできている点 → 誤解・不足（正しい説明つき）→ 次に考えるとよい問い（1〜2個）。
4. `understanding.json` を更新：ノードごとに level（1回で最大+2）、status=assessed、history に評価の要約（回答の原文は保存しない）、next_review（DOC-04 §8）。
5. ユーザーの疑問を `questions.json` に追加（origin=user）。
6. 予測が含まれていれば `forecasts.json` に記録（owner=user）。
7. `python3 tools/validate.py` → コミット（`data: L{ID} 評価`）→ push。
