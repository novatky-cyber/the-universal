# 開発パイプライン（Architect / Implementer / Reviewer / Tester）

## Architect（設計）
- 要件（DOC-01）から外れていないか確認する。外れる場合は実装せず、レポートの「提案」に書く。
- 設計書（DOC-02/03/04/05）を先に改訂し、版と変更履歴を更新する。
- 選択肢があった判断は `docs/adr/NNNN-<題>.md` に記録する（背景／選択肢／決定／理由／影響）。

## Implementer（実装）
- ブランチ `dev/<内容>` で、設計書どおりに実装する。
- 外部依存は最小限に（Python標準＋インストール済みライブラリ、ビューアはCDNのthree.jsのみ）。
- `python3 tools/check_all.py` を通す。

## Reviewer（独立レビュー：サブエージェント）
依頼文には、差分（`git diff main...`）、関連する設計書の該当節、本節だけを渡す。実装の経緯は渡さない。
確認項目：
1. 設計書との一致（仕様の漏れ・逸脱）
2. バグ（境界値、NaN、空データ、参照切れ、例外処理）
3. iPhone Safari での動作上の懸念（ビューア）
4. 可読性・保守性（後のセッションが理解できるか）
5. セキュリティ・プライバシー（個人情報、外部への送信）
出力：指摘ごとに「重要度（高/中/低）・場所・内容・修正案」。

## Tester（テスト）
- `check_all.py` の結果を確認する。
- ビューアの変更時は、Playwright でiPhone相当（390×844）とiPad相当（820×1180）のスクリーンショットを撮り、表示を確認する。
- 結果を `CHANGELOG.md` の該当版に一行で残す。
